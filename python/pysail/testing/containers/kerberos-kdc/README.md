# Kerberos integration test infrastructure

This directory contains the Docker-based Kerberos KDC used by the PySail Hive
Metastore integration tests.

## Architecture

Three processes share the test infrastructure:

| Process | Hostname | Role |
| --- | --- | --- |
| KDC container | `sail-kerberos-kdc` | MIT KDC and admin server; creates principals and keytabs |
| HMS container | `sail-kerberos-hms` | Apache Hive Metastore 4.0.0 with Kerberos SASL enabled |
| Python probe | CI host | Starts Sail, acts as the GSSAPI client, and asserts catalog behavior |

The pytest fixture in `pysail.testing.containers.hms` starts both containers
on one Docker network. Each credentials case runs the probe in a fresh Python
process so GSSAPI environment and credential-cache state cannot leak between
tests.

## Files

- `Dockerfile` builds a Debian Bookworm image with `krb5-kdc` and
  `krb5-admin-server`.
- `kdc-entrypoint.sh` creates the KDC database and starts `krb5kdc` and
  `kadmind`.
- `bootstrap-kdc.sh` creates the service and client principals, writes their
  keytabs, and generates the HMS container's `krb5.conf`.

## Configuration choices

The service principal deliberately uses `localhost` instead of the HMS
container hostname. This prevents GSSAPI host-based name canonicalization from
turning a container hostname into a CI runner's internal FQDN and missing the
principal stored in the KDC.

The host `krb5.conf` generated by `_host_krb5_config()` disables DNS realm and
hostname lookup, reverse lookup, and short-name qualification. It also maps
common local and CI domains to `SAIL.TEST`. `udp_preference_limit = 1` forces
the host client through the KDC's published TCP port; containers can still use
the KDC's standard port on their shared network.

Each probe sets `KRB5CCNAME` with an explicit `FILE:` prefix. Some Kerberos
implementations require the cache type to locate the test's isolated ticket
cache correctly.

Production HMS configuration also supports the Hadoop-compatible `_HOST`
placeholder in service principals. These tests pass the complete principal
directly so the integration contract is independent of DNS canonicalization.
