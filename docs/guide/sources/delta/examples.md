# Examples

<!--@include: ../../_common/spark-session.md-->

## Basic Usage

::: code-group

```python [Python]
path = "file:///tmp/sail/users"
df = spark.createDataFrame(
    [(1, "Alice"), (2, "Bob")],
    schema="id INT, name STRING",
)

# This creates a new table or overwrites an existing one.
df.write.format("delta").mode("overwrite").save(path)
# This appends data to an existing table.
df.write.format("delta").mode("append").save(path)

df = spark.read.format("delta").load(path)
df.show()
```

```sql [SQL]
CREATE TABLE users (id INT, name STRING)
USING delta
LOCATION 'file:///tmp/sail/users';

INSERT INTO users VALUES (1, 'Alice'), (2, 'Bob');

SELECT * FROM users;
```

:::

## Data Partitioning

You can work with partitioned Delta tables using the Spark DataFrame API.
Partitioned Delta tables organize data into directories based on the values of one or more columns.
This improves query performance by skipping data files that do not match the filter conditions.

::: code-group

```python [Python]
path = "file:///tmp/sail/metrics"
df = spark.createDataFrame(
    [(2024, 1.0), (2025, 2.0)],
    schema="year INT, value FLOAT",
)

df.write.format("delta").mode("overwrite").partitionBy("year").save(path)

df = spark.read.format("delta").load(path).filter("year > 2024")
df.show()
```

```sql [SQL]
CREATE TABLE metrics (year INT, value FLOAT)
USING delta
LOCATION 'file:///tmp/sail/metrics'
PARTITIONED BY (year);

INSERT INTO metrics VALUES (2024, 1.0), (2025, 2.0);

SELECT * FROM metrics WHERE year > 2024;
```

:::

## Schema Evolution

Delta Lake validates incoming data against the existing table schema.
Set `mergeSchema` to `true` to add fields during an append or overwrite.
Enable `delta.enableTypeWidening` to apply supported type widening to existing fields.
For the table created by the basic Python example, append a row with a new `age` column:

```python
path = "file:///tmp/sail/users"
df = spark.createDataFrame([(3, "Carol", 30)], "id INT, name STRING, age INT")
df.write.format("delta").mode("append").option("mergeSchema", "true").save(path)
```

Use `overwriteSchema` with a full overwrite to replace the schema of an existing Delta table:

```python
df = spark.createDataFrame([(1, "Alice")], "id BIGINT, name STRING")
df.write.format("delta").mode("overwrite").option("overwriteSchema", "true").save(path)
```

For the `users` table from the SQL example, you can enable type widening and widen `id` from `INT` to `BIGINT`:

```sql
ALTER TABLE users SET TBLPROPERTIES ('delta.enableTypeWidening' = 'true');
ALTER TABLE users ALTER COLUMN id TYPE BIGINT;
```

## DML Operations

Use `DELETE`, `UPDATE`, and `MERGE INTO` to modify Delta tables.
For the `users` table from the SQL example:

```sql
UPDATE users SET name = 'Robert' WHERE id = 2;

DELETE FROM users WHERE id = 1;

MERGE INTO users AS target
USING (SELECT * FROM VALUES (2, 'Bob'), (3, 'Carol') AS s(id, name)) AS source
ON target.id = source.id
WHEN MATCHED THEN UPDATE SET name = source.name
WHEN NOT MATCHED THEN INSERT (id, name) VALUES (source.id, source.name);
```

To use deletion vectors for subsequent DML operations, enable them on the table:

```sql
ALTER TABLE users SET TBLPROPERTIES ('delta.enableDeletionVectors' = 'true');
UPDATE users SET name = 'Caroline' WHERE id = 3;
```

With deletion vectors enabled, an update can append replacement rows and mark the old rows as deleted without copying all unaffected rows in the same data file.
See [DML Operations](./features#dml-operations) for the supported modes.

## Defaults and Identity Columns

You can define default values and generated identity columns when creating a Delta table:

```sql
CREATE TABLE orders (
  id BIGINT GENERATED ALWAYS AS IDENTITY,
  status STRING DEFAULT 'new',
  quantity INT
)
USING delta
LOCATION 'file:///tmp/sail/orders'
TBLPROPERTIES ('delta.feature.allowColumnDefaults' = 'supported');

INSERT INTO orders (quantity) VALUES (10), (20);
INSERT INTO orders (status, quantity) VALUES (DEFAULT, 30);

SELECT * FROM orders ORDER BY id;
```

Identity columns generate values when omitted, while column defaults supply values for omitted defaulted columns.
Use `GENERATED BY DEFAULT AS IDENTITY` to also accept explicit identity values.

## Time Travel

You can use the time travel feature to query historical versions of a Delta table.
A timestamp selects the most recent table version committed at or before that time.

```python
df = spark.read.format("delta").option("versionAsOf", "0").load(path)
df = spark.read.format("delta").option("timestampAsOf", "2025-01-02T03:04:05.678").load(path)
```

The SQL equivalents use `VERSION AS OF` and `TIMESTAMP AS OF`:

```sql
SELECT * FROM users VERSION AS OF 0;
SELECT * FROM users TIMESTAMP AS OF '2025-01-02T03:04:05.678';
```

Choose a version or timestamp from the table's retained history.

## Column Mapping

You can create Delta tables with `name` or `id` column mapping.
Choose the mode when creating the table; the examples below use separate new locations.

```python
df.write.format("delta").option("delta.columnMapping.mode", "name").save(
    "file:///tmp/sail/mapped_by_name"
)
df.write.format("delta").option("delta.columnMapping.mode", "id").save(
    "file:///tmp/sail/mapped_by_id"
)
```

Existing Delta tables with column mapping can be read as usual.

## Catalog-Managed Tables

For a table using the Delta `catalogManaged` feature, use its name in a configured [Unity Catalog](../../catalog/unity):

```python
df = spark.table("my_catalog.my_schema.my_table")
```

Replace the identifier with the table's catalog, schema, and name.
The `catalogManaged` feature uses catalog-ratified commits to reconstruct table snapshots.
See [Catalog Integration](./features#catalog-integration) for supported operations.
